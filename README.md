# 长度前缀分帧与粘包处理（从 0 实现）

本仓库是起始环境：只有规格、分块样本、期望输出与现场记录，没有实现代码。目标是从 0 写一个流式分帧引擎——字节一块块喂进去，吐出完整的帧，每帧带它在流里的偏移区间与长度。命令行用 Python 3.13 标准库，另生成一个双击即开的单文件页面，用来排查边界错乱。无第三方依赖、无构建步骤。

## 1. 范围

要做：

- `framing.py`：分帧引擎（库）。`Framer` 提供 `feed(chunk: bytes) -> list[Frame]`，返回本次喂入后新产出的帧（按流顺序）；`finish() -> dict` 结束整条流并给出处置结论（字段见第 4 节，不适用写 `None`）。`Frame` 至少提供 `start`（帧起始偏移，含前缀）、`end`、`length`（帧体长度）。
- `main.py`：命令行入口，读分块样本目录，输出帧清单与处置结论，或生成页面。
- `frames.html`：由命令行生成的单文件页面，数据内联、双击即开：把字节流画成一条长条，按块切出边界，帧画成色块，没有归入任何帧的区间标红；切分与标记必须取自同一次运行的引擎输出。
- `tests/`：用标准库 `unittest` 写的测试。

不做：不解析帧体内容（不认协议语义、不做校验、不重传、不排序）；不做网络收发，输入只有本地分块文件；不做并发与增量落盘；页面不联网、不加载任何外部资源，也不做移动端适配。

## 2. 口径与公式

帧格式写死，不能改：

- 前缀 4 字节，无符号大端序（网络字节序），取值是紧随其后的帧体字节数 N。
- 合法帧体长度 0 ≤ N ≤ 65536（64 KiB）；N = 0 是合法帧（零长帧）。
- 帧的偏移区间为 [start, end)，左闭右开：start 是前缀首字节在整条流里的下标（流首字节为 0），end = start + 4 + N；内容长度就是 N。
- 偏移以整条流为单位，不按块重置；块边界只影响喂入节奏，不影响结果。
- 已产出帧的区间按 start 升序、互不重叠、首尾相接：第 k 帧的 end 就是第 k+1 帧的 start；正常结束时最后一帧的 end 等于流长。

## 3. 状态机与数据结构

引擎只需持有：未消费缓冲、已消费偏移、帧计数、终态标记。

| 状态 | 条件 | 动作 |
| --- | --- | --- |
| 等前缀 | 缓冲不足 4 字节 | 继续接收 |
| 等帧体 | N > 0 且缓冲不足 N 字节 | 继续接收 |
| 产出帧 | N = 0，或缓冲已够 4 + N 字节 | 产出帧，缓冲前移 4 + N |
| 停摆 | 读到的前缀 > 65536 | 立即停止，丢弃缓冲与后续字节（已产出的帧保留） |

- 零长帧消费完前缀就产出，不需要帧体字节。
- 空块（0 字节）等价于没喂：不推进偏移、不产生帧。
- 喂入块可以落在任意位置：前缀只到一半、帧体跨两块甚至三块，都由同一套缓冲逻辑覆盖。
- 停摆发生在读出前缀的那一刻：不得为了「看完整条数据」继续攒字节，也不得跳过该帧继续解析后面的字节。
- 流结束：缓冲为空即正常结束；剩 1~3 字节是「前缀不完整」；有完整前缀但帧体不足是「帧体不完整」；已停摆则终态是「超长帧」。

## 4. 输入输出与文件格式

分块输入 `samples/chunks/<用例>/`：

- `chunk-000.bin`、`chunk-001.bin`……文件名三位十进制、从 000 连续递增，按文件名升序就是流顺序；每个文件是一次喂入的字节，0 字节文件表示一次空读。
- `manifest.tsv` 每行 `<块文件名>\t<块字节数>\t<该块结束后的累计偏移>`，UTF-8/LF，供人核对；命令行以 `chunk-NNN.bin` 升序为准，并与 manifest 交叉校验，对不上按样本错误处理。
- 单块不超过 1 MiB（1048576 字节）。

帧清单（`--frames`）：每行 `<序号> <起始偏移> <结束偏移> <内容长度>`，序号从 1 起，十进制、单空格分隔、无表头。

处置结论（`--report`）：固定 6 行，键名与顺序写死，`-` 表示该字段不适用：

    status ok
    frames 3
    stream-bytes 27
    tail-start -
    tail-bytes 0
    declared-length -

`status` 四取一：`ok`、`oversize`、`incomplete-prefix`、`incomplete-body`。`tail-start` 与 `tail-bytes` 描述没有归入任何帧、也不再参与解析的尾部区间 [tail-start, stream-bytes)，没有这样的区间时写 `-` 和 `0`。`declared-length` 只在能读出前缀时给出（超长帧与帧体不完整都写声明的长度），其余写 `-`。

两份输出都是 UTF-8、LF、末行带换行，逐字节可复现。

命令行：`python3 main.py <用例目录> [--frames <路径|->] [--report <路径|->] [--html <路径>]`（Windows 上用 `wsl -- python3`）。`--frames` 默认 `-`；`--report` 默认不输出；`-` 表示 stdout，两者同时为 `-` 属于用法错误。输出必须流式写出，不得先整份拼接。退出码 0 表示正常跑完（含超长帧、不完整尾部这类已定义的处置），1 表示用法、读写或样本错误。

## 5. 性能与验收口径

预算见 `samples/expected-budget.txt`：未消费字节数不超过 2 MiB；基准是 32 MiB 的流（32 块，每块 1 MiB），端到端单次不超过 3.0 秒（跑 3 次取中位数），峰值常驻内存不超过 128 MiB，且比 726 字节用例的峰值高出不超过 16 MiB。

验收：

1. 逐用例运行命令行，`--frames`、`--report` 写出的文件与 `samples/expected/<用例>.frames.txt`、`<用例>.report.txt` 逐字节一致：序号、偏移、行序、终结位置都要对上。
2. 同一用例重复运行、以及不同 `PYTHONHASHSEED` 下，帧清单与处置结论逐字节相同。
3. 32 MiB 用例不得整份读入内存：常驻内存不随流长增长，未消费缓冲不超过 2 MiB。
4. `--html` 生成的 `frames.html` 双击可开（`file://` 直接打开），无网络请求、无外部引用；长条上的块边界、帧色块与标红区间，同帧清单、处置结论出自同一次运行；标红的恰好是 `tail-*` 描述的那一段。

## 6. 样例说明

`samples/chunks/<用例>/` 与 `samples/expected/<用例>.frames.txt`、`<用例>.report.txt` 一一对应，`samples/expected/disposition.md` 是逐用例的处置说明，`samples/notes.md` 是现场记录。全部文件 UTF-8、LF。

| 用例 | 覆盖点 | 块数 | 流字节 | 帧数 | 终态 |
| --- | --- | --- | --- | --- | --- |
| `01-prefix-split` | 前缀正好跨块（2+2 与 1+3） | 5 | 27 | 3 | `ok` |
| `02-body-split` | 帧体跨两块，中间夹一次空读，有块一次吐出两帧 | 4 | 436 | 4 | `ok` |
| `03-frame-span-three` | 一帧跨三块 | 3 | 726 | 3 | `ok` |
| `04-zero-length-run` | 连续四个零长帧，其中一个的前缀被切开 | 3 | 34 | 6 | `ok` |
| `05-oversize` | 声明 65537 的前缀，当场停摆并丢弃其后字节 | 4 | 37 | 2 | `oversize` |
| `06-incomplete-prefix` | 流结束时只剩 2 字节，凑不满前缀 | 2 | 24 | 2 | `incomplete-prefix` |
| `07-incomplete-body` | 声明 64 字节，只到 25 字节就结束 | 2 | 37 | 1 | `incomplete-body` |
| `08-scale-32mib` | 32 MiB、块固定 1 MiB，含零长帧与 65536 上限帧 | 32 | 33554432 | 23455 | `ok` |

`samples/**` 只读，不得改动。
